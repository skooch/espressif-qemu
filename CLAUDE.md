# Local Build Notes

- 2026-04-04: Use `gmake` for `tests/tcg/Makefile.target` on macOS. BSD `make` does not support GNU make directives such as `undefine`, and the Xtensa TCG makefiles rely on them.
- 2026-04-04: This machine does not currently have `gmake` installed. For local verification without installing new tools, use the Xtensa TCG source files (`crt.S`, `vectors.S`, `linker.ld.S`) with `xtensa-esp32s3-elf-gcc`, then run the resulting ELF under `build/qemu-system-xtensa -M sim -cpu esp32s3 -semihosting -icount 6 -kernel <elf>`.
- 2026-04-05: `xtensa-esp32s3-elf-gcc` is installed under `/Users/skooch/.rustup/toolchains/esp/xtensa-esp-elf/esp-15.2.0_20250920/xtensa-esp-elf/bin/` but is not on `PATH` in a plain shell. Use the full path or activate the sibling repo's `mise` env before relying on Xtensa cross-build commands.
- 2026-04-04: Do not include `include/hw/xtensa/esp32s3_intc.h` from common qtest code. That header pulls in Xtensa CPU internals via `target/xtensa/cpu.h` and fails qtest builds. If a qtest only needs an interrupt source ID such as `ETS_CACHE_IA_INTR_SOURCE`, prefer a local constant over the broad SoC register headers to avoid unrelated macro redefinition warnings. For ESP32-S3 specifically, `ETS_CACHE_IA_INTR_SOURCE` is `56`; the classic ESP32 `include/hw/misc/esp32_reg.h` value `68` is not interchangeable.
- 2026-04-05: Running `tests/functional/*.py` directly with the system Python on this machine fails unless `pycotap` is available. For ad-hoc local runs, use `uv run --with pycotap python3 tests/functional/<test>.py` plus the usual `QEMU_TEST_QEMU_BINARY`, `QEMU_BUILD_ROOT`, and `PYTHONPATH=python:tests/functional` environment.
- 2026-04-05: Raw `python3` helpers that instantiate `QEMUMachine` can fail on this machine under Python 3.14 with `RuntimeError: There is no current event loop in thread 'MainThread'`. For ad-hoc scripts, create and set an asyncio event loop first, or prefer the existing functional-test entrypoints that already handle the environment correctly.
- 2026-04-05: When rebuilding minimal Xtensa ROM stubs with `/Users/skooch/.espressif/tools/xtensa-esp-elf/esp-15.2.0_20250929/xtensa-esp-elf/bin/xtensa-esp-elf-gcc`, pass `-mtext-section-literals`. Without it, the linker can fail with `dangerous relocation: l32r: literal placed after use` on these hand-written ROM layouts.
